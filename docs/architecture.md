# 架构

## 独立录入服务

[录入服务](../app/intake-service.mjs)拥有上传批次、照片及不可变提取、共用材料、题目、每次原作答、老师批改、AI 判断、待处理决策与修改历史。[HTTP adapter](../app/intake-http.mjs)提供同源 JSON 编辑接口和流式照片上传接口，[独立入口](../app/intake-server.mjs)可以在不加载复习模块时运行；浏览器通过接口操作，不直接访问数据库。

[完整错题本入口](../app/http-app.mjs)组合相同的录入 handler、兼容导入入口与复习服务。前后端分离是服务职责与接口边界，不要求每次同时启动两个写同一数据目录的进程。独立运行或多实例开发应使用各自的数据目录与端口。

录入以题目为中心，照片是来源，批次是本次处理上下文。题目与每次原作答分开；共用文章和必要图形作为材料关联。数值、条件或所求问题不同的题分别保留。同题新作答与重拍来源不能混为一条。决策背景见[题目中心的录入边界](adr/question-centered-intake.md)。

## 持久化与证据

[录入存储](../app/intake-store.mjs)使用现有 SQLite，图片仍保存在本地文件。提取结果作为原始证据保存，人工修改使用版本检查并记录前后值。重新出现的识别内容不会覆盖人工题干、答案、批改或状态；需要对照的差异保留在记录中。

题目核对状态、每次原作答状态、可能错因确认和复习批阅结果相互独立。确定结果自动保存，未完成核对不阻止留存。照片中只有题目时不伪造一次作答；可见但无法转成文字的字迹或绘图，可凭明确存在证据与原图区域保留。

老师明确判错、且没有与 AI 明确冲突时可以标错；AI 无法判断不等于冲突。没有老师批改时，AI 需在题目完整、作答清晰且有明确错误依据时才自动标错。其他情况保持待确认；状态不代表掌握。

人工补录、拆分、合并和移除都保留来源及历史。拆分未分配的作答留在归档父题；批次查询沿明确拆分或合并谱系显示后续题目，不凭全局照片身份把其他批次的题目引入。已建立的复习会话保留自己的题目快照。

## 两阶段本地去重

照片先按内容指纹确认字节相同；文件名和大小只是线索。相同照片跨批次复用提取结果，批次清单仍独立。[本地匹配](../app/intake-matching.mjs)使用本地图像像素特征给出相似候选，不能据此自动丢弃新作答或批改。用户可以继续识别，或明确选择已有照片复用。

提取后先用本地题干、数值、条件、单位、选项、共用材料与必要图形证据寻找重复候选。仅排版、空格或题号差异可以匹配；图形描述不足以证明配图完全相同。候选需要明确选择新题、同题新作答或同次作答重拍，不静默合并，不让 LLM 扫描全库。

## 本批题目与答题纸关联

照片中的题目和作答分别提取。自动关联要求本批材料有一致的可见文档标识，或明确的标题/学科等证据，再结合独立题号找到唯一题目；不依赖模型拼接标识的顺序，也不只凭题号关联。

本批材料未结束处理时，不提前认定答题纸孤立。对应明确则正常保存；对应不唯一时题目保存、作答暂存，允许用户在本批题目中指定。只有答题纸时保留原图及告警，不建虚构题目，也不查询历史题目认领。重复照片的既有提取仍参与本批关联，旧批次的告警与归属不会因此改写。

## 接口与恢复

录入接口以 `/api/intake/` 为前缀，覆盖批次提交/进度/结果/失败重试，照片及原始提取，题目筛选与编辑，原作答和批改/状态编辑，材料编辑、重复决策、未关联作答指定，以及补录/拆分/合并/移除。

照片通过 multipart/form-data 上传：requestId 是文字字段，photos 是最多30个文件字段，每张不超过15MiB。[上传接收器](../app/intake-upload.mjs)使用 Busboy 背压逐段落入本地私有临时目录，验证后录入服务逐张读取和发布原图；浏览器直接传 File，不构建整批 base64。成功、格式错误或断连后清理本次暂存文件。每个实例同时接收一批并允许两批等待，超额返回429，客户端保留同一请求重试。兼容 base64 JSON 上传最多24MiB；正常照片入口仍支持30张、每张15MiB。普通编辑请求最多1MiB，包含多题内容的拆分请求最多24MiB。

批次提交及会新增记录的命令带请求编号；相同编号和相同内容复用结果，内容冲突明确拒绝。编辑可携带预期版本，避免覆盖已更新记录。保留的草稿同时保留首次编辑的预期版本，其他表单保存后的刷新不把新版本号套到旧草稿上。剩余草稿在读取失败时继续阻止无提示离开。新增命令保存结果未确认时，由[客户端待确认命令](../app/intake-command-client.js)按动作和目标题目保存不可变原路径、内容、请求编号和表单快照。普通草稿取消或切换不会删除命令；返回表单恢复原内容并冻结，补录使用全局待确认项。页面上的确认入口可以直接找回结果，包括拆分后已经归档的父题。重复确认共享在途请求，只有确认成功或明确校验失败后才结束该命令。待确认入口在当前页面生命周期内有效；全页刷新或关闭触发提醒，SQLite 中的已提交记录继续保留。保存及恢复操作在提交前捕获导航、对话框代次和编辑上下文，服务端确认与刷新完成后复核；旧回调只更新结果和计数，不能关闭较新的表单或强制打开旧题。照片证据的异步读取使用同一上下文保护。已经确认但尚未刷新掉的原表单及其镜像保留确认结果，继续显示原提交并冻结；即使刷新失败也保留已确认内容，直到表单成功替换。再次保存先展示原结果，不再创建命令。正常完成后关闭或刷新为新的表单，后续新输入独立提交。确定结果与待处理部分分别持久化，单项失败不撤销其他已完成题目。

原图以临时文件写入后重命名发布。模型识别完成后的 SQLite 写锁只重试保存，不重复推理；排队项可继续，已中断的推理需明确重试。迟到结果按占用标记核对，不能覆盖后续重试。刷新、重启不自动重放已提交推理。关闭时停止接收请求、取消模型并等待在途文件与请求结束后再关闭数据库。

## 兼容导入和复习

[原单图导入模块](../app/paper-import.mjs)继续支持维护脚本的旧入口及去重恢复协议。旧题目、原图、核对状态和复习记录迁入新录入读取模型时保持 ID 与原字段；缺乏证据的旧状态保持未知，不重新判错；创建历史也使用保存的旧状态。兼容入口的更新及录入同步在同一事务中完成，已移除记录可以补充历史事实但不会重新出现在有效题目中。

[复习服务](../app/review-service.mjs)通过录入服务的题目 catalog 获得核对题目及快照，管理自己的复习会话、作答、提示、批阅和异议。直接使用旧复习模块的调用者可通过[兼容 catalog](../app/review-catalog.mjs)读取旧库；正式组合服务注入录入 catalog。复习模块不修改录入表。

[Codex runtime](../app/codex-runtime.mjs)统一管理 app-server 就绪、JSONL 请求、事件归属、取消、超时和连接失效。[图片识别说明](../app/codex-client.mjs)使用录入提取结构；复习提示和批阅保留各自说明。不自动重放已提交推理。

## 验证与升级

自动测试以真实 HTTP 接口为主要验收边界，使用临时 SQLite、临时图片与模型替身；本地匹配另用真实合成像素验证。它们不读取真实试卷，也不能证明真实模型识别准确率。浏览器交互和合成图片的真实 Codex 验证作为补充证据。

切换版本前，在任务空闲时运行 `node scripts/verification/verify-architecture-data.mjs --snapshot`。它在写锁下备份完整 SQLite、保存应用表记录、独立于记录的列名元数据及原图摘要，并拒绝仍在处理的导入、录入或批阅。升级后不带参数核验快照中各表原字段与来源文件；新列允许增加，旧值与复合来源关系不能丢失。快照及报告在 Git 忽略目录，通用数据恢复界面尚未提供。
