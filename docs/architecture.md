# 架构

## 试卷导入任务 module

`app/paper-import.mjs` 集中管理图片校验、内容去重、原图保存、识别排队、待核对落盘以及任务恢复。浏览器和目录批处理通过相同的 HTTP adapter 访问它，批量脚本不读取 SQLite 或服务器原图路径。

相同内容的图片复用进行中或已完成的任务。不同图片按顺序识别。排队中尚未调用模型的任务可以恢复；识别中断的任务保留失败状态及原图，只有明确重新提交才会再次调用模型。旧任务结果与题目关联保留，首次迁移只补充内容指纹及处理占用字段。

原图及作答图片先写同目录临时文件，再重命名发布，失败写入不会截断旧原图。SQLite 写锁暂时阻止排队任务时，队列等待后重试，不提前调用模型。批处理分别计算排队与识别等待时间，等待截止标为尚未完成。

## Codex 调用 module

`app/codex-runtime.mjs` 管理进程就绪、JSONL 请求、每次调用的事件归属、结束、取消、超时与连接失效。`app/codex-client.mjs` 保留图片识别的业务说明；提示和批阅的说明留在复习 module。

调用方无需先建立连接。进程退出会使当次调用失败；下次调用可以启动新进程，但不会自动重放已提交的模型推理。真实 stdio 与内存 stdio adapter 穿过同一个运行 interface 进行验证。

取消在初始化和创建线程期间也能立即结束该调用者的等待，共享初始化供其他调用者继续使用。启动确认丢失或中断失败时，关闭对应连接与进程，避免遗留推理；此时共享该连接的其他调用也会失败，由用户决定是否重试。

## 复习作答 module

`app/review-service.mjs` 继续集中管理题目快照、答案隐藏、提示使用、结果分类、验证记录隔离和异议。提交和提示都先以条件更新占用本次作答，再进行异步文件或模型处理。

每次占用有独立标记，只有该次占用仍有效时才能落盘结果。并发请求不能同时批阅同一作答；中断前的迟到结果不能覆盖重试后的新结果。文件保存或模型处理失败不计为做错。

作答文字在占用时保存；新图片路径在文件完整发布后按占用标记提交。中断保存时继续保留此前已保存的图片，过期回调生成的新图片及时移除。

## 运行与验证

`app/http-app.mjs` 是浏览器及批量入口共享的 HTTP adapter，`app/server.mjs` 只负责组合本地依赖和启动、关闭。SQLite 的磁盘和内存用法共用实现，没有额外引入其他数据库或模型提供方。

关闭时先停止接收请求并取消模型，等待 HTTP 连接排空，超时断开遗留连接；仍在执行的请求和文件保存完成后才允许调用方关闭数据库。

`npm test` 覆盖模块行为和真实 HTTP 路径，使用临时目录、内存 SQLite 及假 Codex 进程，不读取真实试卷、不消耗模型额度。

本机切换前可用 `node scripts/verify-architecture-data.mjs --snapshot` 创建一致的数据库快照，切换后运行 `node scripts/verify-architecture-data.mjs` 核对旧记录和原图。快照与核对报告均在 Git 忽略目录内。
