# 米多错题本：开源项目功能调研

调研日期：2026-10-25。目标：寻找适合孩子日常学习、能补充当前 Codex 驱动错题本的功能。

## 结论

建议优先做三个闭环：**每天少量到期复习、针对错因的一道变式验证、纸质练习结果回流**。这些能力可以复用现有题目、复习作答和批阅历史，比扩展通用聊天、堆积题库或增加复杂 Agent 编排更贴近当前使用场景。

以下项目事实来自官方仓库、官方文档及许可证；“米多建议”是本次调研的产品判断，不代表项目方的结论。没有安装运行这些项目，也没有验证其宣传的识别准确率、教学效果或性能。未向外部上传本仓库真实试卷、图片、数据库或凭据。

## 当前米多的基础

先通过 code-review-graph 缩小范围，再核对 `README.md`、[业务术语](../glossary.md)、[架构](../architecture.md)、`app/review-service.mjs` 与 `tests/review.test.mjs`。

- 已有整页图片拆题、人工核对入库、原图保留、可能错因，以及 Codex 生成提示与批阅。
- 已有提交前隐藏旧答案，区分独立做对、提示后做对、仍不会、待确认；异议和测试记录有单独处理。
- 当前推荐按最近一次正式批阅结果及距今天数排序，尚不是按每题下一次到期时间调度；提示是单层文本，并非多轮诊断。
- README 明确列出的待接入能力包括跨图片合并、自动追问、重复题提示、备份恢复等。下文不把演示原型视为已上线能力。

## 项目比较

### 1. wrong-notebook：最贴近家庭使用的直接参考

[margrop/wrong-notebook](https://github.com/margrop/wrong-notebook) 是 [wttwins/wrong-notebook](https://github.com/wttwins/wrong-notebook) 的分支；两者不要当成两套独立设计重复计数。分支仓库标注 MIT。

官方 README 描述了拍照识题、人工编辑、同知识点变式、筛选组卷打印，并将试卷作答结果记入原题历史；也支持完整学习数据备份。[功能与说明](https://github.com/margrop/wrong-notebook#readme)

**米多建议：**引入“题目→练习版本→本次作答”的关系。打印时给每题稳定编号，做完后拍照或手动回填，结果进入现有复习历史。变式属于原题的练习证据，但保留独立题干和答案快照。

**需要区分：**该项目用固定 1/2/4/7/15/30 天间隔，并以 AI 掌握概率达到 50% 标记已掌握；这些是其产品规则，不能据此证明孩子真正掌握。其 PWA 缓存界面资源，题目数据仍从服务器读取，不能等同完整离线练习。[复习与 PWA 说明](https://github.com/margrop/wrong-notebook#readme)

### 2. 智卷：让拆题与识别结果容易核对

[xiaozhejiya/error_correction](https://github.com/xiaozhejiya/error_correction)（智卷），AGPL-3.0。官方列出 PDF/图片导入、题目边界识别、跨页去重、OCR 框叠加原图、手写擦除，以及绑定错题上下文的教学对话。[官方功能列表](https://github.com/xiaozhejiya/error_correction#功能)

**米多建议：**核对界面点击题目时，高亮它在原图中的位置；允许修正边界、关联另一页的补充题干。把“不确定在哪里”直接显示出来，减少家长来回寻找。

**取舍：**手写擦除只能生成额外的练习视图，不能覆盖原作答证据；几何图、单位和小数点要核对。先借鉴交互，再评估是否需要增加 OCR 模型与部署依赖。代码复用前另核对该项目许可证。

### 3. Anki + ts-fsrs：复习安排与每日负担

[Anki](https://github.com/ankitects/anki) 是间隔重复项目。官方手册提供每日新卡/复习上限、难题反复失败的处理、相关卡片暂缓，以及 FSRS 调度设置。[Anki 调度手册](https://docs.ankiweb.net/manual/deck-options)

[ts-fsrs](https://github.com/open-spaced-repetition/ts-fsrs) 是 MIT 许可的 TypeScript 调度工具集，可产生调度状态与复习日志；官方中文说明提供调用示例。[ts-fsrs 中文说明](https://github.com/open-spaced-repetition/ts-fsrs/blob/main/README_CN.md)

**米多建议：**首页给“今天建议做 3–5 题”，显示入选理由和下次复习日期；同一知识点的相似题分散出现。连续失败时转入补讲或家长协助，避免反复推同一题。

**接入边界：**数学解题、语文表达与闪卡回忆不同，不能直接把现有四种批阅结果映射成 FSRS 四档评分。尤其“待确认”和处理失败不能作为遗忘事件，“提示后做对”也不等于独立回忆成功。先建立可解释的简单到期规则，积累真实记录后再评估 FSRS；需要分别检验原题记忆和知识迁移。

### 4. Kolibri：孩子做题，家长看到需要帮助的地方

[learningequality/kolibri](https://github.com/learningequality/kolibri)，MIT。官方平台以离线学习为核心，提供 learner/coach/admin 角色、课程和测验分配、即时反馈及学习进度报告。[官方产品说明](https://learningequality.org/kolibri/about-kolibri/)

**米多建议：**孩子首页只展示今天任务、继续作答和求助；家长页面处理核对、异议和复习安排。周报挑出“哪些题从提示后做对变成独立做对”“哪里仍需要协助”，每条结论链接具体作答记录。

**取舍：**家庭使用可以先做两个视图，无需引入完整学校账户和班级系统。米多的 Codex 推理需要联网；可把已确认题目和已保存作答做成本地可用，但不能声称离线 AI 批阅。

### 5. MistakeBook：重复题、历史记录和数据可携带性

[Liangbiaoyong/MistakeBook](https://github.com/Liangbiaoyong/MistakeBook) 面向考研场景。官方 README 描述相似题提示与合并、周期统计、变式，以及 Markdown 存题、SQLite 作索引、JSONL 保存复习事件的设计。[官方说明](https://github.com/Liangbiaoyong/MistakeBook#readme)

**米多建议：**区分“同张图片重复上传”和“不同试卷又做错了同一道题”。后者关联到既有题目，但新增一次出错证据；合并时保留每次来源与历史。再增加可恢复的数据备份，包含数据库、原图、复习图片与版本信息。

**取舍：**不必为了 Markdown 存储重写现有 SQLite 架构。参考它对事件历史和可导出的重视即可。本次未确认明确开源许可证，作为公开源码的设计参考，不作为已确认可复用的代码来源。

### 6. 补充参考 MathCrew：针对错误搭台阶

[freesoft/MathCrew](https://github.com/freesoft/MathCrew) 面向 1–6 年级，官方列出计算/概念/步骤/粗心分类、错误后的辅助练习、题目缓存、分知识点表现和奖励机制。[功能列表](https://github.com/freesoft/MathCrew#features)

**许可证核对纠正：**虽然宣传使用 open-source 字样，实际 [LICENSE.md](https://github.com/freesoft/MathCrew/blob/main/LICENSE.md) 是含额外条款的 PolyForm Strict，限制用途、修改和分发。本报告把它单列为可见源码的灵感参考。

**米多建议：**根据本次错误给一个更小的台阶，例如先找单位“1”，再计算；缓存已核对的变式题以减少等待。奖励“愿意重试、说清理由、主动发现错误”。不必复制四 Agent 架构，也不直接采纳“粗心”的自动标签；米多现有“可能错因待确认”更适合保留。

### 7. OpenTutor：让下一次教学真正使用上次的错误

[LEARNableLabs/opentutor](https://github.com/LEARNableLabs/opentutor) 的官方方法文档描述先提问再解释的教学流程，并由会话记录生成确定性指令：补讲、调整难度、换情境重测、改变题目问法。这比单纯把旧聊天放进上下文更值得参考。[教学方法与局限](https://github.com/LEARNableLabs/opentutor/blob/main/docs/methodology.md)

**米多建议：**把“同一概念连续失败，需要补先修”“原题会做，下一次换问法”等规则交给应用保存和执行，Codex 负责生成具体追问与讲解。建立小型误解记录，关联多道题及证据，不把模型猜测直接变成事实。

**限制：**官方明确 SM-2 只接在 Telegram，Web 使用较弱的指令式复习；生成课程未经系统专家审查，且没有长期保留率对照数据。可以借鉴教学控制方式，不能据此认定课程和学习效果可靠。

## 建议实施顺序

以下均为米多的候选设计，尚未实现，也没有在孩子身上验证效果。

| 顺序 | 功能 | 孩子实际体验 | 最小验收标准 |
| --- | --- | --- | --- |
| 1 | 每日少量到期复习 | 打开就知道今天做哪几题，完成后可以结束 | 有每日上限、入选理由、下次日期；待确认/失败不按做错处理；同日反复提交不虚增进度 |
| 2 | 一道针对错因的变式 | 原题会做后，换种问法再试一次 | 变式明确标记为生成题；保存题干/答案/来源关系；可人工核对；不与原题重复计为两个薄弱知识点 |
| 3 | 分层提示与错因追问 | “先想一想→一个线索→局部步骤”，有需要再展开 | 每层提示独立记录；提示后成功不计独立做对；孩子可以否认 AI 对错因的猜测 |
| 4 | 打印练习与回填 | 纸上做题，拍照后能找到对应记录 | 题目编号稳定；答案独立打印；批阅有待确认入口；重复回填不新增重复作答 |
| 5 | 家长周报 | 家长看到本周进步和下一步协助点 | 每个判断可追溯；不把样本少的正确率当掌握率；不纳入测试作答 |
| 6 | 语义重复题关联与备份恢复 | 家长少整理，换电脑不丢学习历史 | 合并可核对；来源、作答不丢；在临时目录完成恢复核验 |

### 最值得先试的一条学习路径

原错题独立重做 → 如卡住则给一层提示 → 做对后隔天再独立试 → 再用一道同知识点变式检查 → 家长看到对应证据。

例如分数应用题：孩子原题算对，但不知道为什么以某个量作单位“1”。下一次不只换数字，可以改问“这句话里把谁看作整体？为什么？”再回到计算题。这个例子是本报告的设计建议，具体追问仍需按题意和孩子的作答生成。

掌握状态建议先用可解释描述：“原题独立做对过”“隔天仍能独立做对”“变式也做对过”“仍需协助”。不要直接显示一个由 LLM 自报的精确掌握百分比。初期目标是取得可靠的学习证据，再决定何时减少复习。

## 优先观察的效果

试用时记录：家长每天整理耗时、孩子是否能自主完成一小轮、提示后成功能否转为隔天独立成功、变式是否暴露未理解处、AI 识别/批阅的待确认比例。仅增加题目数量、调用次数和连续打卡，不足以判断产品有没有帮助。

本次只增加调研文档，没有修改应用或运行模型批阅。后续若进入实施，建议先做“每日复习上限与到期日”，再接“一题一变式”的小范围验证。
