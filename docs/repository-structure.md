# 目录组织与文档维护

新增或迁移文件先按职责选目录，再命名。现有文件同样遵守规则；不以兼容旧布局为理由增加例外。目录与文件类型的可执行约束在 [doc-guard.json](../config/doc-guard.json)，修改约束必须同时说明职责变化并补检查用例。

## 目录职责

| 位置 | 职责 |
| --- | --- |
| 根目录 | 项目入口 README、代理指令 AGENTS、包管理与工具入口配置、桌面启动器 |
| app/ | 正式应用的服务端和浏览器实现 |
| docs/ | 长期维护的产品、架构、开发和术语文档；index.md 是总入口 |
| config/ | 仓库检查的声明式规则 |
| scripts/checks/ | 离线、可重复执行的质量检查入口 |
| scripts/operations/ | 接受用户输入的导入等维护命令，从仓库根目录运行 |
| scripts/verification/ | 需要本机模型或数据的手动验证，从仓库根目录运行，不进入自动测试 |
| scripts/lib/ | 脚本共用模块，不作为用户命令 |
| tests/ | 隔离自动测试及测试辅助模块 |
| prototypes/ | 按实验主题分子目录的独立演示，不作为正式功能依据 |
| .github/ | CI 与 PR 模板 |
| data/、samples/ | 本地数据库和真实素材，必须 Git 忽略 |
| .scratch/ | 临时报告、一次性个人操作脚本和实验输出，必须 Git 忽略 |

## 命名

目录和普通文件使用英文小写 kebab-case，名称表达职责，不使用日期、版本、final、new、old、backup 等副本后缀。测试使用 `功能名.test.mjs`；Node 模块使用 `.mjs`，浏览器代码使用 `.js`，文档使用 `.md`。配置文件遵循其工具固定名称，例如 package.json、eslint.config.mjs；只有根目录 README.md、AGENTS.md 使用大写文档名称。

文档按主题维护一份当前说明，术语集中在 [glossary.md](glossary.md)。演示以目录表达主题，HTML 入口命名 index.html。迁移时修正 import、命令、文档和 HTML 引用，不保留旧路径空壳。

## 防止文档腐化

所有长期文档从 [文档索引](index.md) 可达。链接用相对路径、准确大小写；源码文件引用优先使用 Markdown 链接。命令示例从仓库根目录执行。临时报告可以说明存放位置，但不能成为理解、运行项目所必需的文档。

修改行为时，作者同步更新对应文档：用户流程与边界更新 README；模块契约和恢复行为更新 architecture；开发命令与 CI 更新 development；业务用语更新 glossary；目录职责更新本页和检查配置。PR 审查者核对这些说明与源码，无法自动判断的语义一致性不得用检查通过代替。

`npm run docs:check` 检查 Git 管理及未忽略的新文件：目录和命名、必需文档、文档入口可达性、Markdown 本地文件链接、代码路径引用和 npm run 命令。不会扫描本地数据库、真实图片或调用模型。外网链接可用性和业务描述的准确性由审查负责；此检查不验证 Markdown 标题锚点。

删除或重命名文件应在同一提交修复引用；所有检查通过才算迁移完成。测试数量、单台电脑上的题目数量和临时验证进度放在 PR 证据或本地报告，不写成长期产品事实。
