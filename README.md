# 米多错题本

版本：0.1.0。

当前版本通过本机 Codex app-server 识别照片。点击“选择照片并识别”可一次选择多张 PNG、JPEG、WebP，整页或局部都可以，不必先建试卷档案或填写分类。全部可见题目会保存，题目、孩子每次原作答、老师批改和 AI 判断分别留存。

## 照片录入与核对

一次选择形成一个上传批次，每张照片不超过15MB，一次最多30张。相同照片复用已有结果，本地相似图片或重复题目进入待处理提示；只有明确选择后才复用或关联，不因为题型相似静默丢弃。数值、条件或问题变化属于不同题。

本批同时有题目页和答题纸，且可见材料标识与题号能唯一对应时，正常关联。只有题目的照常保存，不伪造原作答；只有答题纸时保留原图及告警，不搜索历史题目认领。对应不明时作答暂存，可以手动指定本批题目，其余结果不受阻塞。

“全部题目”可按作答状态、标签或知识点筛选，查看每次原作答和曾错过的证据。点开题目可对照原图区域，修改题干、老师批改、作答和状态；也可补录漏题、拆分、合并或移除误识别内容。共用文章、配图来源与历史继续保留，初始识别和人工修改可以追溯。

尚未保存的修改在切换或关闭时会提醒。若补录、拆分、合并或新增作答的保存结果暂时无法确认，表单会保留本次提交内容并暂停编辑；再次点击保存先确认原结果，避免重复新增。切换题目或关闭表单后，仍可点击页面上的“确认上次保存结果”找回这次操作；关闭或刷新整个页面前会提醒尚未确认的提交。

老师明确判错或信息充分时 AI 发现明确错误，可以自动标记错误并显示依据。老师和 AI 明确冲突、缺少作答或看不清时不会直接算错，其余默认待确认。可以之后手动修改；作答状态不表示已经掌握。

## 推荐复习与批阅

点击左侧“复习”，再点击“推荐复习”。清单读取已核对、进入复习范围的题目，显示推荐理由；选题后开始独立作答。原答案、错因和讲解在提交前隐藏。第15题使用依据原图关系绘制的独立几何示意图，避免显示带有旧答案的整张试卷。

可输入文字或打开本次作答图片，提交后由 Codex 真实批阅。提示也通过 Codex 生成，使用情况单独记录。结果分为独立做对、提示后做对、仍不会、待确认。信息不足或异议不计错；处理失败可保留作答后重试。原错因和掌握状态不会因批阅自动改变。

会话、题目快照、每次作答、提示、批阅及异议保存在本地 SQLite，可从复习入口继续或查看历史。作答图片位于 `data/review-images/`。验证记录不纳入真实推荐统计。

## 运行

本机需要 Node.js 24 或以上，以及已经登录的 Codex CLI。

首次运行先执行 `npm ci` 安装锁定版本的开发工具。

多 worktree 开发先执行 `npm run bootstrap`，再用 `npm run dev` 启动独立端口，详见 [Worktree 初始化](docs/worktrees.md)。

双击 `start-notebook.cmd`，或在此目录运行：

```sh
npm start
```

打开 <http://127.0.0.1:4318/>。当前提供桌面浏览器界面，尚未打包为独立安装程序。图片识别使用 Codex 当前配置及可用模型，调用需要联网并使用相应账户额度；没有另行写入 API 密钥。Codex 可执行文件未被自动发现时，可设置 `MIDO_CODEX_BIN`。

## 独立录入接口

录入服务可以不加载复习模块而单独运行：

```sh
node app/intake-server.mjs
```

默认监听 <http://127.0.0.1:4319/>，提供 `/api/intake/` 接口，不托管浏览器页面。`MIDO_INTAKE_PORT` 可覆盖端口，`MIDO_INTAKE_DATA` 可指定独立数据目录；同时运行多个实例时不能共用同一个数据目录。日常使用 `npm start` 的完整界面即可，完整应用组合的是相同录入接口。服务边界见[架构](docs/architecture.md)。

## 数据

原图位于 `data/images/`，录入批次、题目、原作答、批改与复习记录位于 `data/notebook.sqlite`，均留在本机；识别与批阅时相关题目、作答或图片会发送给 Codex 模型服务。数据库和图片均不进入 Git。真实导入题目与最初的合成测试作业分别保留，合成试题不进入默认复习推荐。

本地试卷样本统一放在 `samples/papers/`。`data/`（含 SQLite 的 WAL、SHM 文件）和整个 `samples/` 目录均加入 `.gitignore`；复制到其他电脑时，需单独迁移这些本地文件。目录外的原始图片不移动。

## 验证

```sh
npm run check
```

隔离测试覆盖批量录入、两阶段去重、本批答题纸关联、作答历史与编辑、升级核验、恢复、Codex 调用生命周期和复习并发提交，通过真实 HTTP 入口验证，不调用模型或修改本地真实数据。架构说明见 [docs/architecture.md](docs/architecture.md)，业务用语见 [docs/glossary.md](docs/glossary.md)。

`npm run check` 顺序运行 ESLint、doc guard 和隔离测试；也可单独使用 `npm run lint` 或 `npm test`。GitHub Actions 在 Windows、Linux 的 Node.js 24 环境中执行同样的检查。开发到 PR 的流程见 [docs/development.md](docs/development.md)。

```sh
python scripts/verification/make-vision-fixture.py
npm run verify:codex
```

生成图片仅依赖测试环境的 Pillow。验证通过本地图片输入，检查页面标记、数学与语文两题拆分、学生原作答和结构化分析。测试题文字与页面标记没有放进模型的文字提示中。

目录批处理通过运行中的错题本执行：

```sh
node scripts/operations/batch-import-papers.mjs samples/papers --plan
node scripts/operations/batch-import-papers.mjs samples/papers --run
```

`--plan` 只向本机检查图片是否已导入，不调用模型；`--run` 复用相同内容的旧单图导入任务并将新结果放入待核对区。批处理仍使用兼容单图接口；多图批内答题纸关联从浏览器批次入口开始。
